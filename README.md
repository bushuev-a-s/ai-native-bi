# AI-Native BI Agent — первый тестовый вариант (прототип)

Платформа: загружаешь сырые CSV → общаешься с агентом на естественном языке →
получаешь описание данных, ответы, графики и дашборды. Данные остаются локально, модель подключается
по OpenAI-совместимому API (модель организаторов, vLLM и т.п.) или работает локально через Ollama.

## Быстрый старт

```bash
cp .env.example .env     # затем заполните модель (см. ниже)
bash run.sh              # http://localhost:8501
```
`run.sh` сам выбирает режим по `LLM_BASE_URL` из `.env`: внешний адрес (модель организаторов) → запускаются
только БД и приложение; адрес не задан → дополнительно Ollama в контейнере (`gpu` или `cpu`), модель скачивается
при первом запуске (`docker compose logs -f ollama-cpu`). Принудительно: `--remote`, `--gpu`, `--cpu`.

### Своя модель

Провайдер по умолчанию **openai** (OpenAI-совместимый API). Всё задаётся в `.env`, код менять не нужно:
- модель организаторов или любой внешний сервер: `LLM_BASE_URL=https://<хост>/v1`, `LLM_MODEL=<имя>`, `LLM_API_KEY=<ключ>`;
- локальный Ollama: `LLM_BASE_URL` не задавать (в docker подставится `http://ollama:11434/v1`), `LLM_MODEL=qwen2.5:7b-instruct`;
- родной API Ollama: `LLM_PROVIDER=ollama`, `LLM_BASE_URL=http://localhost:11434` (нужен редко).
Старые `OLLAMA_URL` и `OLLAMA_MODEL` больше не читаются. Ключ не коммитьте: `.env` в `.gitignore`.

Организаторы будут проверять на моделях семейства Qwen 27B/35B, поэтому финальную проверку делаем на них;
у моделей с «размышлениями» блоки `<think>` снимаются автоматически.

## Архитектура

```
CSV ──► loader (кодировка, разделитель, даты) ──► PostgreSQL (сырые таблицы как есть)
                                                     │
                       profiler (типы, пропуски, топ-значения, период, дубликаты, связи по id)
                                                     │  «память о данных» → в промпт
вопрос ─► router ─► overview / explain / query / rechart / dashboard / clarify / reject
                      query: LLM → SQL → safety (только SELECT, READ ONLY, timeout, LIMIT)
                             └─ ошибка? → LLM видит ошибку и исправляет (до 2 раз)
                             → ответ простым языком + авто-график (+ SQL под спойлером)
```

| Файл | Что делает |
|---|---|
| `core/loader.py` | загрузка произвольного CSV, автоопределение формата |
| `core/profiler.py` | профиль таблиц, поиск связей, текст схемы для LLM |
| `core/agent.py` | маршрутизация, text-to-SQL с самоисправлением, графики, дашборды, контекст сессии |
| `core/safety.py` | валидатор SQL (один SELECT, чёрный список, служебные таблицы закрыты) |
| `core/charts.py` | авто-выбор типа графика и его построение (Plotly) |
| `core/prompts.py` | все промпты в одном месте |
| `core/db.py` | PostgreSQL, транзакции READ ONLY, хранение дашбордов в `_bi_dashboards` |
| `app.py` | чат + вкладка «Дашборды» (Streamlit) |

## Скорость

На типичный вопрос приходится 2 вызова модели (SQL и короткий пересказ). Намерение определяется правилами, а не отдельным
вызовом модели; тип графика подбирается без модели; одиночные числа пересказываются шаблоном; описание данных
(«Что передо мной?») считается один раз; виджеты дашборда считаются параллельно и кешируются. Под каждым ответом в интерфейсе
показано время: «⏱ итого · вызовов модели · БД». Замер по набору вопросов: `uv run python scripts/bench.py`.

Настройки (необязательные, см. `.env.example`): `ROUTER_MODE` (`rules` или `llm`), `NARRATION` (`auto`, `llm`, `template`),
`CHART_LLM`, `HISTORY_TURNS`, `SQL_MAX_TOKENS`, `DASHBOARD_MAX_WIDGETS`, `DASHBOARD_CACHE_TTL`.

## Что проверено, а что нет

Проверено тестами (`tests/test_core.py`, 10 тестов, на SQLite и заглушке LLM): загрузка CSV с разными форматами,
профиль и поиск связей, защита SQL, логика агента (роутер, самоисправление SQL, контекст, дашборды).

**Не запускалось** в окружении разработки (не было сети): Streamlit-интерфейс, реальный PostgreSQL, реальная модель.
Первый запуск у вас может вскрыть мелкие ошибки — несите их в чат, поправим. Качество text-to-SQL зависит от модели:
на 7B иногда будут ошибки, самоисправление это смягчает; при наличии GPU попробуйте модель побольше (`LLM_MODEL`).

## Известные ограничения

- CSV читается целиком в память — для файлов в сотни МБ нужен потоковый `COPY`.
- Десятичная запятая (`1,5`) и экзотические форматы дат не распознаются автоматически.
- Профиль считается по выборке (до 100 000 строк на таблицу), число строк — точное.
- Дашборд-виджеты строятся по SQL от LLM; при смене данных SQL перезапускается, но спецификация не пересоздаётся.
