# AI-Native BI Agent

## Быстрый запуск

bash run.sh

Переменная, с названием модели: LLM_MODEL
Измените на модель, на которой будете проводить тестирование

## Команда **Overfitting squad** · Кейс №2 «AI-Native BI Система» (ИАЦ)

Локальная платформа для аналитики «на лету»: загружаете сырые CSV (или подключаете свою PostgreSQL),
общаетесь с агентом на русском языке и получаете описание данных, ответы на вопросы, графики и дашборды.
Всё работает на вашем компьютере: PostgreSQL, языковая модель (Ollama) и приложение запускаются в Docker.
Облачные сервисы не нужны, весь стек открытый.

## Что умеет

- **Знакомство с данными.** «Что передо мной?»: структура, период, число строк, связи между таблицами, простым языком.
- **Вопросы по содержанию.** Значения, смысл полей, топы, дубликаты, группировки. Агент сам пишет SQL, проверяет его и при ошибке исправляет.
- **Графики по запросу.** Вид подбирается под вопрос, меняется фразой «покажи иначе» или «сделай круговой».
- **Дашборды.** «Создай дашборд по основным показателям»: сохраняется, открывается из чата и из вкладки «Дашборды», удаляется.
- **Диалог с контекстом.** «А теперь то же самое в другом виде». История чатов сохраняется в базе и переживает перезапуск.
- **Сырые данные как есть.** Кодировка, разделитель (`,` `;` табуляция `|`), форматы дат и десятичная запятая определяются при загрузке. Вручную разделитель можно выбрать в боковой панели.
- **Большие файлы.** Файлы от 50 МБ грузятся потоково через `COPY` (файл на 180 МБ загружается быстрее 30 секунд на нашей машине).
- **Честные отказы.** На расплывчатые вопросы агент просит уточнить, на запросы изменить или удалить данные отказывает.

## Требования

- Docker и Docker Compose v2 (Docker Desktop на Windows и macOS).
- Около 10 ГБ свободного места: образы и модель `qwen2.5:7b-instruct` (≈4,7 ГБ).
- Видеокарта NVIDIA с драйвером и NVIDIA Container Toolkit ускоряет модель, но не обязательна: без неё работает режим CPU, только медленнее.
- Проверено: Windows 11 + WSL2 + Docker Desktop, видеокарта с 4 ГБ VRAM, `qwen2.5:7b-instruct`. ⟨ЗАПОЛНИТЬ: добавьте другие конфигурации, на которых запускали⟩

## Быстрый старт (локальная модель)

```bash
git clone <адрес репозитория>
cd ai-native-bi
cp .env.example .env        # настройки по умолчанию подходят, править не обязательно
bash run.sh                 # сам выберет режим GPU или CPU и запустит всё в фоне
```

Для внешней модели по API этот способ не подходит: см. раздел «Как сменить модель или подключить модель по API».

Дальше откройте **http://localhost:8501**. При первом запуске скачивается модель, это занимает несколько минут.
Пока она качается, индикатор модели в боковой панели красный, потом станет зелёным.
Прогресс загрузки: `docker compose logs -f ollama-gpu` (или `ollama-cpu`).

На Windows запускайте скрипт из Git Bash или из WSL, не из PowerShell.

То же вручную:

```bash
docker compose --profile gpu up -d --build     # или --profile cpu
docker compose down                            # остановить (данные сохраняются)
```

> Внимание: `docker compose down -v` удаляет том с базой данных, то есть все загруженные таблицы, чаты и дашборды.

## Как сменить модель или подключить модель по API

Модель задаётся переменными в файле `.env` в корне репозитория (создаётся из `.env.example`), код менять не нужно.
Настройки читаются при старте, поэтому после правки `.env` приложение нужно перезапустить (команды ниже).

| Что нужно | Что менять в `.env` | Как запускать |
|---|---|---|
| Другая локальная модель в Ollama (так запускает жюри) | только `LLM_MODEL=<имя модели Ollama>` | `bash run.sh` |
| Модель по API: организаторов, vLLM, LM Studio, облачный ключ | `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | `docker compose up -d --build`, **не** `run.sh` |
| Сервер модели на этом же компьютере, но вне Docker | `LLM_BASE_URL=http://host.docker.internal:<порт>/v1`, `LLM_MODEL` | `docker compose up -d --build` |
| Приложение запускается без Docker | те же переменные в окружении | `uv run streamlit run app.py` |

### Вариант 1. Другая локальная модель (Ollama)

В `.env` задайте имя модели из каталога Ollama и запустите проект:

```
LLM_MODEL=qwen2.5:14b-instruct
```
```bash
bash run.sh
```

Если проект уже запущен, достаточно `docker compose --profile gpu up -d` (или `--profile cpu`): контейнеры пересоздадутся с новой моделью.
Контейнер Ollama при каждом старте выполняет `ollama pull $LLM_MODEL`: при первом запуске нужен интернет (веса скачиваются один раз и хранятся в томе `ollama`).
Если скачать не удалось, сервер продолжит работу с уже имеющимися моделями. Имя должно в точности совпадать с именем в каталоге Ollama (`docker compose exec ollama-gpu ollama list`),
а модель должна помещаться в память: подробности в [Benchmarks.md](Benchmarks.md).

### Вариант 2. Модель по API (внешний сервер)

Платформа работает с любым OpenAI-совместимым сервером: она обращается к `<LLM_BASE_URL>/chat/completions` и проверяет доступность через `<LLM_BASE_URL>/models`.

**Шаг 1. Узнайте у провайдера** адрес API (обычно заканчивается на `/v1`), точное имя модели и ключ.

**Шаг 2. Проверьте доступ** из терминала (WSL или Git Bash):

```bash
curl -s https://<хост>/v1/models -H "Authorization: Bearer <ключ>"
```

В ответе в поле `id` должно быть имя модели так, как вы запишете его в `LLM_MODEL`. Если ответ пришёл, адрес и ключ верные.

**Шаг 3. Заполните `.env`:**

```
LLM_PROVIDER=openai
LLM_BASE_URL=https://<хост>/v1
LLM_MODEL=<имя из поля id>
LLM_API_KEY=<ключ>
```

**Шаг 4. Запустите без локальной модели:**

```bash
docker compose up -d --build
```

Не используйте `run.sh`: он поднимает локальный Ollama и пытается скачать в него модель с именем из `LLM_MODEL`.
Если Ollama уже был запущен раньше, его можно остановить: `docker compose --profile gpu stop ollama-gpu`.
Если стек уже работает, для смены модели достаточно `docker compose up -d app`: контейнер приложения пересоздастся с новыми настройками.

**Шаг 5. Проверьте.** В боковой панели индикатор модели должен показать «`<модель>` · openai (доступна)».
Какие настройки реально получил контейнер: `docker compose exec app env | grep LLM_` (в выводе виден ключ: не вставляйте его в чаты и не показывайте на видео).
Ключ не коммитьте: `.env` в `.gitignore`.

**Если у сервера свои особенности**, добавьте в `.env`:

| Проблема | Что добавить |
|---|---|
| Модель «размышляет» (Qwen3 и подобные): ответы медленные или обрываются | `LLM_EXTRA_PARAMS='{"chat_template_kwargs": {"enable_thinking": false}}'` для vLLM, `'{"think": false}'` для Ollama; блоки `<think>` платформа из ответа вырезает сама. Если размышления отключить нельзя, увеличьте `SQL_MAX_TOKENS` (например, до 4096) |
| Ответ обрезается | `LLM_MAX_TOKENS=2048` |
| Таймаут на долгих запросах | `LLM_TIMEOUT=600` (по умолчанию 300 секунд) |

JSON в `.env` берите в одинарные кавычки, как в примере.

**Если не работает:**

| Что видите | Причина и что делать |
|---|---|
| «сервер модели недоступен» | Адрес неверный или недоступен из контейнера. Внутри контейнера `localhost` это сам контейнер: для сервера на вашем компьютере пишите `host.docker.internal`. Проверьте также, что индикатор успевает получить ответ за 3 секунды |
| «модель … не найдена на сервере (есть: …)» | `LLM_MODEL` не совпадает с `id` из `/models`: скопируйте имя оттуда |
| HTTP 401 или 403 | Неверный или просроченный `LLM_API_KEY` |
| HTTP 404 | Адрес без `/v1` или неверный путь; для локального Ollama модель не скачана |
| HTTP 429 | Провайдер ограничил частоту запросов: подождите и повторите |
| Индикатор красный, но сервер отвечает на чат | Сервер не поддерживает `/models`, а индикатор проверяет именно его. Задайте тестовый вопрос: чат может работать |

## Первое использование

1. В боковой панели выберите файлы CSV (по умолчанию можно загружать до 1 ГБ) и нажмите **«Загрузить в базу»**.
   Разделитель определяется автоматически; если таблица загрузилась «кашей» или с одной колонкой, удалите её (🗑 рядом с названием),
   выберите разделитель вручную и загрузите файл заново.
2. Спросите: **«Что передо мной?»**. Затем, например:
   - «Сколько строк в каждой таблице?»
   - «Какие значения встречаются чаще всего в колонке …?»
   - «Покажи наглядно, как это распределено»
   - «Создай дашборд по основным показателям»
   - «А теперь покажи то же самое в другом виде»
3. Слева список чатов: можно начать новый, вернуться к старому или удалить. Готовые дашборды лежат на вкладке «Дашборды».

Тестовые данные: `python scripts/make_sample_data.py` создаст три связанные таблицы в `sample_data/`
(разделитель `;`, даты `13.03.2024`, дубликаты, пропуски, просадка платежей в июле).

### Подключение к существующей базе PostgreSQL

Платформа видит таблицы схемы `public` любой PostgreSQL, строит профиль и связывает таблицы по значениям идентификаторов, предварительная обработка не нужна.
Запросы агента выполняются только на чтение (`READ ONLY`, ограничение времени и числа строк).
В этой базе платформа создаёт собственные служебные таблицы `_bi_dashboards`, `_bi_chats`, `_bi_messages`, поэтому нужны права на создание таблиц.

- **В Docker** адрес базы задан в `docker-compose.yml` (сервис `app`, переменная `DATABASE_URL`, по умолчанию контейнер `db`), `.env` на него не влияет.
  Чтобы подключить свою базу, замените это значение на её адрес `postgresql+psycopg2://<пользователь>:<пароль>@<хост>:5432/<база>`.
  Хост должен быть доступен из контейнера; для базы на вашем компьютере пишите `host.docker.internal`.
- **Без Docker** задайте `DATABASE_URL` в окружении.

Работает только PostgreSQL; ClickHouse пока не поддерживается.

## Запуск без Docker для приложения (разработка)

Нужен Python 3.14 и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
docker compose up -d db                 # PostgreSQL на localhost:5432
docker compose --profile cpu up -d ollama-cpu   # или ollama-gpu; модель скачается сама
export DATABASE_URL=postgresql+psycopg2://bi:bi@localhost:5432/bi
export LLM_BASE_URL=http://localhost:11434/v1   # Ollama на этом же компьютере
uv run streamlit run app.py             # http://localhost:8501
```

Приложение само не читает `.env` (его подхватывает только `docker compose`), поэтому при запуске без Docker переменные нужно экспортировать в окружение.

## Настройки

Образец `.env` — [.env.example](.env.example). Значения по умолчанию заданы в `core/config.py`.

**Важно для Docker:** `docker-compose.yml` передаёт в контейнер приложения только перечисленные ниже переменные из столбца «Через `.env` в Docker».
Остальные из `.env` в контейнер не попадают, и менять их можно только в окружении при запуске без Docker (или добавив строки в раздел `environment` сервиса `app`).

| Переменная | По умолчанию | Что делает | Через `.env` в Docker |
|---|---|---|---|
| `DATABASE_URL` | `postgresql+psycopg2://bi:bi@localhost:5432/bi` (в Docker задан в compose: контейнер `db`) | база данных | нет, см. выше |
| `LLM_PROVIDER` | `openai` | `openai` для OpenAI-совместимого API, `ollama` для родного API Ollama | да |
| `LLM_BASE_URL` | `http://ollama:11434/v1` в Docker, `http://localhost:11434/v1` без Docker | адрес сервера модели | да |
| `LLM_MODEL` | `qwen2.5:7b-instruct` | имя модели | да |
| `LLM_API_KEY` | `not-needed` | ключ для внешних серверов | да |
| `LLM_MAX_TOKENS` | не задан | лимит длины ответа модели | да |
| `LLM_TIMEOUT` | `300` | таймаут запроса к модели, секунды | да |
| `LLM_EXTRA_PARAMS` | пусто | JSON, добавляемый в запрос к модели (отключение «размышлений») | да |
| `LLM_NUM_CTX` | `8192` | размер контекста Ollama | да |
| `LLM_KEEP_ALIVE` | `30m` | сколько Ollama держит модель в памяти | да |
| `ROUTER_MODE` | `rules` | `rules`: намерение определяют правила без вызова модели; `llm`: отдельный вызов модели | да |
| `NARRATION` | `auto` | пересказ результата: `auto`, `llm` (всегда моделью) или `template` (никогда моделью) | да |
| `HISTORY_TURNS` | `4` | сколько последних реплик диалога идёт в запрос к модели | да |
| `SQL_MAX_TOKENS` | `1024` | лимит длины SQL-ответа модели | да |
| `CHART_LLM` | `0` | `1`: вид графика выбирает модель (медленнее) | нет |
| `DASHBOARD_MAX_WIDGETS` | `4` | число виджетов в дашборде | нет |
| `DASHBOARD_CACHE_TTL` | `300` | секунды хранения результатов виджетов | нет |
| `FAST_LOAD_MIN_MB` | `50` | файлы от этого размера грузятся через `COPY` | нет |
| `MAX_ROWS` | `1000` | максимум строк в ответе запроса | нет |
| `QUERY_TIMEOUT_MS` | `15000` | ограничение времени запроса, миллисекунды | нет |
| `PROFILE_SAMPLE_ROWS` | `100000` | сколько строк таблицы берётся для профиля (число строк считается точно) | нет |
| `NARRATE_MAX_TOKENS`, `OVERVIEW_MAX_TOKENS`, `DASHBOARD_MAX_TOKENS` | `220`, `300`, `1600` | лимиты длины ответов модели по задачам | нет |

## Безопасность и работа офлайн

- Агент выполняет только один `SELECT` за запрос: изменение, удаление данных и служебные таблицы (`_bi_*`) ему недоступны. Запросы идут в транзакции `READ ONLY` с ограничением времени и числа строк.
- После первого запуска платформа работает без интернета: образы, зависимости и модель скачиваются один раз.
  Поисковые системы платформа не использует. Список доменов, к которым нужен доступ при установке, см. в [Architecture.md](Architecture.md).

## Известные ограничения

- Поддерживается PostgreSQL; ClickHouse не реализован.
- Числа с разделителем тысяч (`1,234`) не угадываются и остаются текстом: запятая может быть и десятичной, и разделителем тысяч.
- Над таблицей в CSV не должно быть строк-заголовков отчёта и строки `sep=;`: разделитель определится верно, но колонки прочитаются неверно.
- Качество text-to-SQL зависит от модели. На 7B-моделях возможны ошибки в сложных запросах; самоисправление их смягчает, на моделях побольше результат стабильнее.
- Сложные аналитические сценарии (лаги, корреляции, сегментация, прогноз) выполняются через SQL, который пишет модель. Модуль `core/analytics.py` (поиск дубликатов, регистр инструментов `TOOLS`) к диалогу не подключён.
- Чаты общие для всех, кто открыл приложение: привязки к пользователю нет.
- Дашборд-виджеты строятся по SQL от модели; при смене данных SQL пересчитывается, а сама спецификация не пересоздаётся.

## Частые проблемы

| Симптом | Что делать |
|---|---|
| `invalid option name: set: pipefail` при запуске `.sh` на Windows | Git сохранил переводы строк CRLF: `git add --renormalize .`, запускать из Git Bash |
| Индикатор модели красный | Модель ещё скачивается или сервер недоступен: `docker compose logs -f ollama-gpu` (или `ollama-cpu`), проверьте `LLM_BASE_URL` |
| Модель отвечает очень медленно | Проверьте `docker compose exec ollama-gpu ollama ps`: если в колонке PROCESSING есть CPU, модель не помещается в видеопамять; возьмите модель поменьше или уменьшите контекст. См. [Benchmarks.md](Benchmarks.md) |
| `ModuleNotFoundError: No module named 'pandas'` | Не установлены зависимости: `uv sync` и запуск через `uv run` |
| Порт 8501 или 5432 занят | Остановите другой процесс или поменяйте порты в `docker-compose.yml` |
| Таблица загрузилась с одной колонкой | Выберите разделитель вручную в боковой панели и загрузите файл заново |
