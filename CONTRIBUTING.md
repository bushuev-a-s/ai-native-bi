# Как работаем в репозитории

## Ветки
- `main` — стабильная версия, всегда запускается. Напрямую не коммитим.
- `dev` — общая ветка интеграции.
- Личные ветки: `feat/<поток>-<что>` (например `feat/agent-prompts`, `feat/ui-dashboards`, `fix/loader-decimal`).

Порядок: ветка от `dev` → маленькие коммиты → Pull Request в `dev` → мердж в `dev`.
В `main` сливает `dev` Саня перед чекпоинтами и финалом.

## Коммиты
Короткое сообщение по сути: `agent: добавил примеры в промпт SQL`, `loader: десятичная запятая`.

## Правила
1. Перед PR запустите `bash run_tests.sh` — все тесты должны проходить.
2. Новая логика ядра — с тестом в `tests/`.
3. **Данные организаторов в репозиторий не коммитим.** Кладите в папку `data/` (она в `.gitignore`).
   В `sample_data/` лежат только сгенерированные тестовые данные.
4. Пароли, токены и `.env` не коммитим.
5. Репозиторий на GitHub делайте **приватным**, пока не уточнили у менторов, что публиковать можно.
6. Одна задача — один Issue (список в `docs/TASKS.md`, создаются скриптом `scripts/create_issues.sh`).

## Первичная настройка (один раз, делает владелец репозитория)
```bash
bash scripts/git_setup.sh https://github.com/<логин>/<репозиторий>.git
```
